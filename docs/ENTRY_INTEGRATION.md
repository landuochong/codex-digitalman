# Codex 入口设计

## 两级入口

1. **标准入口**：通过插件目录、Skill 默认提示词或固定任务触发。它是稳定的核心入口。
2. **左侧快捷入口**：参考 dashi-taskboard 的做法，通过 Codex Desktop 调试协议注入按钮。它只负责缩短路径，是可关闭的增强能力。

公开的插件清单可以声明 Skill、MCP、应用映射和展示信息，但不能据此承诺任意原生侧栏按钮。因此两种入口必须分层实现。

## 可选注入流程

1. Launcher 以专用配置启动 Codex Desktop，并启用受控的 CDP 管道或本机调试端口。
2. 在新文档创建时注入入口脚本。
3. 脚本在侧栏滚动区域定位原生 Plugins 行，克隆其视觉结构，改为“露米休息室”。
4. 点击后发送 `open-digitalman` 主机动作；Launcher 预创建会话并启动数字人服务，但不立即打开外部窗口。
5. 主机把经过校验的环回 origin 和会话 ID 留在控制器中，Renderer 只收到“会话已准备”的事件。
6. 注入器在 Codex 主工作区直接构造人物卡、消息区和输入框；聊天通过受限 CDP binding 由控制器代理，不加载外部页面，也不自动打开独立窗口。
7. `MutationObserver` 仅用于 Codex 重绘后防抖恢复入口和工作区宿主；启动期给予有界重试窗口，连续稳定检查仍失败时停止注入并回退到标准入口。热重连必须撤销旧 Observer 后重新注入。

## 与 dashi-taskboard 的差异

早期方案参考 dashi-taskboard 尝试把环回页面放入 Codex 主工作区，但 26.820.60940 的 CSP 会阻止 iframe，主进程也拒绝动态 webview guest。当前方案改为参考 Codex Dream Skin / QQ Skin：通过 CDP 早期注入、重绘恢复和直接 DOM/CSS 渲染构造内部面板。

## 安全约束

- 调试端口只绑定环回地址；优先使用私有管道。
- 主机绑定使用动作白名单，禁止把任意字符串拼接成 Shell 命令。
- 注入脚本不得读取任务内容、认证信息或页面存储。
- 已确认 26.820.60940 的 `frame-src` 会阻止环回 iframe、`Page.setBypassCSP` 无效且动态 webview 不会 `did-attach`。内部工作区因此不创建任何嵌入浏览器容器，也不关闭 Web 安全策略。
- 提供环境变量或配置项作为总开关，例如 `CODEX_DIGITALMAN_ENTRY_ENABLED=false`。
- 内部面板以显式点击麦克风的语音通话为主；文字输入默认收起，仅作无麦克风权限、ASR 或 TTS 不可用时的降级入口。
- 人物使用 `digitalman` 默认真人角色 `lumi` 的固定白名单待机/动作视频；资源必须限制 MIME/大小，并通过现有版本守卫与 kill switch；不得退回任意 URL 代理、静态陌生人物图片或 iframe。
- 为已验证的 Codex 版本建立兼容表；未知版本直接使用标准入口。

## 入口状态

入口按钮只显示三种状态：未运行、正在启动、已打开。内部面板只保存当前显示所需的最近六条短历史；不读取 Codex 任务正文、认证数据或页面存储，刷新后即丢弃。
